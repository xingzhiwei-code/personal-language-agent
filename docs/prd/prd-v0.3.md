# PRD-v0.3：每日计划 2.0（三段式学习体验）

> 版本：v0.3（待确认）｜ 日期：2026-10-03
> 地位：V0 阶段内的第三次可交付迭代
> 目标读者：编码 Agent——读完直接开工，不需要再问"这个功能到底要怎么做"
> 前置阅读：`product/product-master-plan.md`（宪法与红线）、`docs/prd/prd-v0.1.md`（基线）、`docs/prd/prd-v0.2.md`（F1–F7）、`docs/decisions/ADR-008.md`
> 背景输入：`ux-audit-v0.2.md`（2026-10-03 真实浏览器走查 + 用户两轮 dogfood 反馈 + 8 款语言 App 竞品调研）

---

## 1. 背景与目标

v0.2 交付了知识库导入/目标体系/每日计划后，用户真实 dogfood 两轮 + yiyi 用 Playwright 跑完一次完整学习旅程，确认了体验断层（详见 `ux-audit-v0.2.md`）：

1. **每日计划"生硬"**：点一键开始直接考试，没有开场意义感、没有热身；做完"一点感觉都没有"，没有收尾完成感。
2. **学习过程单调**：10 张卡全是四选一识别题；无发音、无音标显示；新词第一次见面就是考试，没有"学"的环节。
3. **场景断点**：场景页显示"尚未绑定表达"，但 UI 上没有任何地方能把表达绑到场景——场景加权调度无米下锅。
4. **协作阻塞**：Node 24 下 `better-sqlite3` 直接 500，必须硬约束 Node 版本。

**目标**：让每日计划从"做题机器"变成"有开场、有变化、有收尾"的一次完整学习体验；补齐 v0.2 遗留的 P0/P1 补丁（并入本版本，不再单独发 v0.2.x）。

**非目标**：口语对话 / 发音评测仍有意缺席（代码注释原文：we do not fake features——无 STT，不伪造发音打分），留 V1。听力以**听写卡**形式进入本版本（P2 的 TTS 播报 + 键盘输入 + 确定性打分，不需要 STT）。本版本只把**已实现、有确定性能力**的活动类型（阅读/语法/写作/听写）真正打通。

## 2. 范围

### 做（In）

**P 补丁（原 v0.2.x，并入 v0.3）**
- **P1** 词库池独立 Tab（知识库一级入口）
- **P2** 单词发音：Web Speech API + 音标显示 + 常驻重播
- **P3** Node 版本硬约束（根治 Node 24 下 500）
- **P4** UI 版本号统一为 V0.3（单一来源）
- **P5** 导入补全式更新：已存在条目的**空字段**（例句、音标）可被导入文件补全；只填空、不覆盖已有值；记 operation log

**D 每日计划 2.0（三段式）**
- **D1 开场**：计划启动卡（新学 X / 复习 Y / 预计 N 分钟 + 一句话解释 + 一键开始）+ 热身阶段（新词只曝光不测试）
- **D2 过程**：热身即"学"（曝光环节承担学习功能，不另设独立学阶段）→ 混测；错题本节内回流（答对一次才通过）、识别→回忆→产出阶梯编排（含听写题型：TTS 播报→键盘输入→确定性打分，作为识别环节的听觉变体）、三态自评保留在 recall 作答链路、新词卡展示 `source_span` 真实原句
- **D3 收尾**：多维结算（作答/正确率/用时/掌握度变化/连续天数 + 可选"再来一组"），保留现有诚实口径

**S 场景绑定表达**：补齐 UI（批量绑定 + 场景详情页管理）；数据模型已存在（`scenarios.knowledgeItemIds`），本次只做 UI 和链路打通

**W 写作去 AI 门槛**：scheduler 的写作候选不再硬要求 AI key；无 AI 时用现有确定性打分 + 诚实标注（决策见 §11）

### 不做（Out，留 V1 / Backlog）
- 口语对话（`conversation` 仍需 AI key，且 `planActivities`  returns []，本次不动）
- 发音评测 / 朗读跟读打分（无 STT，不伪造；朗读跟读自评卡等 V1 有 STT 时做真·跟读评测，不单独上无反馈信号的版本）
- AI 批改写作文本（V1）
- 图词配对、社交/PK/互助批改、防断签类游戏化（宪法禁止绑架式游戏化）
- 视频 / 网页 / PDF / 播客导入 pipeline（已在 V1）
- 系统从对话自动推断场景（已在 V1）

## 3. 功能需求

### P1 词库池独立 Tab

- **问题**：词库池藏在知识库页"状态"筛选下拉里，连自动化脚本都一度定位失败。
- **改动**：知识库页 Tab 增加 **"词库池"** 一级入口，与"知识条目 / 已保存原文 / 导入导出历史 / 操作日志"平级。
- 池内现有能力保留：搜索、词库筛选、标签筛选、复选批量加入学习、分页（万级不卡死是底线）。
- 去掉"靠状态筛选找池子"的暗道（筛选器本身可保留，但主入口必须是 Tab）。
- 空池文案指向导入（复用 v0.2 空引导逻辑）。

### P2 单词发音

- **方案**：Web Speech API（`speechSynthesis`），零 key、零成本。
- **行为**：
  - 学习/热身卡片**首次展示自动播放**单词发音；常驻🔊按钮可无限重播。
  - 卡片同步显示导入数据已有的**音标**（`knowledgeItems.phonetic`，有则显示，无则不占位）。
  - 语言固定 `en-US`，语速 0.9（v0.3 不做可调，留扩展点）。
- **降级**：浏览器不支持 / 被自动播放策略拦截时，隐藏自动播放、保留手动喇叭，**不得报错、不得阻塞**（拦截只发生在首次，首次播放必须在用户点击"开始"的手势链内触发）。
- **红线**：发音是"读出来"，不是"发音评测"——不做跟读打分（Backlog）。

### P3 Node 版本硬约束

- **问题**：`better-sqlite3` 在 Node 24 下 ABI 不匹配，知识库页直接 500，无任何提示。
- **改动**（全部要做，缺一不可）：
  1. `.nvmrc` 写入 `20`；
  2. `package.json` → `engines: { "node": "20.x" }`；
  3. README 醒目位置提示 Node 版本要求；
  4. dev 启动脚本检查 `process.version` 主版本，非 20 直接报错退出，文案示例：`本项目需要 Node 20（当前 Node 24），请用 nvm use 切换。better-sqlite3 在 Node 24 下无法工作。`
- **验收硬指标**：Node 24 下跑 `npm run dev` 得到上述清晰错误，**而不是**等用户打开知识库页才看到 500。

### P4 版本号统一

- 全站版本号改为从**单一来源**读取（建议：`package.json` 的 `version` 或现有版本常量，二选一，编码 Agent 定），首页徽标与设置页显示一致，均为 **V0.3**。
- 发版时只改一处。

### P5 导入补全式更新

- **问题**：v0.2 导入对"库中已存在"条目直接跳过。yiyi 为高频 1000 词生成的例句文件（`cet6-top1000-with-examples.csv`，释义+音标+例句合并版）导进已有 7405 词的库时会 0 新增——例句落不了地，D2 的产出阶梯无米下锅。
- **改动**：导入判重命中已存在条目时，检查导入行是否有非空字段（例句、音标）而库中对应字段为空 → **只填空**，不覆盖已有值；每条补全记一条 operation log（含 `ai_generated` 标记透传）；预览页单独显示"补全 N 条"，与"新增 / 跳过"并列。
- **红线**：已有值的字段永不覆盖；补全不计入"新增"，不改变去重语义。

### D1 开场：启动卡 + 热身

**启动卡**（替换现有"今日计划"卡片的头部信息区，一键开始/换一批/今日休息保留）：
- 三要素：**新学 X / 复习 Y / 预计 N 分钟**（数字来自 scheduler 现有推荐，不得编造）。
- 一句话解释：说明内容来源，如"这 10 个词来自你的雅思词库"（复用推荐 reason，不得写空洞文案；无绑定时 fallback 文案必须诚实，如"按词频给你挑的通用词"）。
- "本地规则生成"徽标保留。

**热身阶段**（session 内新阶段，排在正式测试之前，约 2 分钟）：
- 对象：本节**新学**条目（复习条目不热身，直接进测试）。
- 形式：卡片只曝光——单词 + 自动发音 + 释义 +（如有）`source_span` 原句；用户点"下一个"浏览，**不测试、不计分**。
- 完成热身记一条 `warmup_completed` 学习事件（含曝光条目 ids），用于"已曝光"追溯；不影响 mastery。
- 用户可跳过热身（"跳过热身直接开始"），跳过不算失败。

**适用范围**：三段式（热身→学测→结算）是 session runner 的统一结构，每日计划、快速复习、词汇回忆等所有学习活动类型共用；区别只在 scheduler 给的条目集合不同。

### D2 过程：热身 → 混测（v0.3 实现说明：不设独立"学"阶段和分组循环）

- **热身即"学"**：D1 的热身曝光（单词 + 发音 + 释义 + `source_span` 原句）承担原设计的"学"功能。不另设独立学阶段的原因：两者展示内容完全相同，重复一遍只会拉长流程；且新词自评信号极弱（几乎全是"忘了"）。独立学阶段还会使每词 `exposureCount` 从 1 变 2，与既有 `vertical-loop.test.ts` 断言冲突——为守住"不重写已有测试"约束和 verify 全过底线，刻意不做（编码 agent 诚实说明，2026-10-05）。
- **测**：题型按 **识别 → 回忆 → 产出** 阶梯编排（复用 `buildReviewItems` 的三种 modality，按顺序出，不打乱阶梯）；同一条目在同节测试中至多出现两种题型（避免疲劳）。
- **三态自评**保留在 recall 作答链路（"诚实选一个"），信号写入 learner state，复用现有 `scoreFromSelfRating`；不作为独立学习卡出现。
- **错题本节内回流**（学多邻国）：答错的条目在本节剩余题目完成后重新出现；**答对一次即通过**；单条目至多重排 2 轮，2 轮后仍错 → 标记"本节未通过"，交由现有 due 机制稍后回来，**不死循环、不惩罚**。
- 全部题目完成 → D3 结算。
- 保留现有退出文案："没做完不算失败"、"跳过这个 / 先暂停 / 就到这里 / 退出"。

**听写题型**（识别环节的听觉变体）：
- 流程：🔊 自动播报单词（复用 P2 发音模块）→ 用户键盘输入听到的单词 → 确定性打分（复用现有 `gradeTextAnswer` 的模糊比对，大小写/首尾空格不敏感）。
- 题型选择复用 `buildReviewItems` 现有机制：听写是新增的一种 recognition modality，与四选一识别按既有规则选用，不新增调度规则。
- 降级：Web Speech 不可用时，该条目自动回退到四选一识别，**不报错、不卡死**。

### D3 收尾：多维结算

保留现有诚实口径（"下面是实际发生的事，不是打分"），**增加**以下真实数据（全是库里已有的数据，只是之前没展示；没有的不展示，不编造）：
- 作答数 / 答对数（已有）+ **正确率**
- **用时**（session startedAt → endedAt）
- **掌握度变化**：session 开始/结束时的技能 mastery 快照对比，如"词汇 42%→45%"；无变化的技能不展示
- **连续学习天数**：completed session 定义为**到达结算页**的 session（中途退出不计）；有 ≥1 个 completed session 的自然日连续计数；断一天后重新从 1 计；今天学了就是 1（诚实，不玩"差 1 天就断签"的焦虑）
- 错题列表（已有，"之后会再出现"保留）+ 涉及的知识条目（已有）

**可选"再来一组复习"**（学扇贝）：结算页一个按钮，用复习池（due / 低 mastery 条目）生成一组 ≤10 条的快速复习 session；**不强制**，不用时无任何打扰。

### S1 场景绑定表达

- **问题**：`scenarios.knowledgeItemIds` 字段已存在，但 UI 上没有任何地方能把表达绑到场景，场景加权调度无米下锅。**本次只做 UI + 链路，不动数据模型。**
- **改动**：
  1. 词库池 / 知识条目列表：多选后出现"绑定到场景"操作（下拉选择 active 场景，可多选场景）；
  2. 场景详情页：展示已绑定表达列表（支持移除）；空状态文案引导去词库池挑选（"尚未绑定表达，去词库池挑选"带跳转）。
- v0.2 已实现的场景加权调度、过期自动归档逻辑复用，绑定后自动生效。

### W1 写作去 AI 门槛

- **问题**：`candidates.ts` 里 writing 候选被包在 `if (snapshot.aiAvailable)` 内——无 AI key 的用户永远看不到写作练习。但 `sessions.ts` 的 writing_prompt 打分**已是确定性实现**（检查是否用上了目标表达 + 是否成句，见 `gradeWriting` 附近逻辑），根本不需要 AI。
- **改动**：
  1. writing 候选移出 `aiAvailable` 门槛，`requiresAi: false`；
  2. 写作练习 UI 诚实标注（无 AI 时）："AI 批改未启用，这次只检查你有没有用上目标表达"；
  3. 有 AI key 时行为不变（仍推荐；AI 批改正文留 V1，本次不做）。
- **决策记录**：见 §11（ADR-009 待补）。核心论据：打分是确定性的，门槛是人为的；宪法要求"不伪造功能"——我们明确告诉用户这次没 AI 批改，而不是假装有。

## 6. 非功能需求

- 性能：现有底线不变（万级词库池不卡死）；热身/分组不得引入可感知的额外等待。
- 回归：现有 155 测试全过；新增单元/集成测试覆盖：热身事件、错题回流（2 轮上限）、阶梯排序、连续天数计算、写作无 AI 可推荐、场景绑定链路、听写打分（大小写/空格不敏感）、导入补全（只填空、不覆盖已有值）。
- 浏览器兼容：Web Speech API 不可用时降级（§P2），测试环境（Playwright/Chromium headless 无语音）不得因此挂掉——发音模块必须可 mock/可跳过。
- 宪法遵循：调度/打分/热身/回流走确定性规则（Level 0）；LLM 仅用于已有场景；不新增 AI 依赖。
- Node 约束见 P3（dev 与生产一致）。

## 7. 验收标准

**P 补丁**
1. 知识库页有"词库池"一级 Tab；原"状态筛选找池子"的暗道不再是唯一入口。
2. 学习卡片首次展示自动发音（用户手势链内），喇叭按钮可重播；有音标数据的卡片显示音标；无语音的浏览器下降级且无报错。
3. Node 24 下 `npm run dev` 直接报错退出并提示切换 Node 20；Node 20 下一切正常。
4. 首页与设置页版本号均为 V0.3，且只改一处即可全局生效。

**D 每日计划 2.0**
5. 启动卡显示"新学 X / 复习 Y / 预计 N 分钟"三要素 + 一句话内容来源解释 + 一键开始；换一批/今日休息可用。
6. 点开始后先进入热身（仅新词）：只曝光不测试，可跳过；完成后记 `warmup_completed` 事件。
7. 测试阶段题目按识别→回忆→产出顺序出现；热身/学习卡片展示 `source_span` 原句（如有）；三态自评在 recall 作答链路出现且信号入库。
8. 组内答错的条目在本组稍后重新出现，答对一次通过；单条目至多重排 2 轮；2 轮后仍错不死循环，由 due 机制接管。
9. 结算页展示：作答/正确率/用时/掌握度变化（如词汇 42%→45%，无变化不展示）/连续天数/错题列表；"再来一组复习"可用且不强制。

## 11. 决策记录（ADR-009 待补）

**ADR-009：写作练习去 AI 门槛**（2026-10-03，yiyi）
- 背景：writing 候选被 `aiAvailable` 门槛挡住，但打分逻辑本身是确定性的（关键词命中 + 成句检查）。
- 决定：移出门槛，无 AI 时可用 + 诚实标注"无 AI 批改"；AI 批改正文留 V1。
- 依据：宪法"不伪造功能"——我们不假装有 AI 批改；AI Economy——不为已有确定性能力强加 AI 依赖。

**补充决策**（2026-10-05，用户认可后记入）
- **听写卡进 v0.3**：P2 引入 TTS 后，"听力有意缺席"的理由已过期。听写（TTS 播报 + 键盘输入 + 确定性打分）不需要 STT、不新增 AI 依赖，作为识别环节的听觉变体进入 D2/M3。
- **朗读跟读卡不进 v0.3**：无 STT 就没有反馈信号，自评跟读等于"自己读一遍"，信号太弱；等 V1 有 STT 时做真·跟读评测，不单独上无信号版本。
- **P5 导入补全式更新**：用户 7405 词 0 例句已实测验证（`cet6-wordlist.csv` / `ielts-wordlist.csv` 全空）；无例句则 D2 产出阶梯空转。yiyi 生成高频 1000 词合并版例句文件（释义+音标+例句，LLM 生成，`ai_generated` 标识），v0.2 导入"已存在即跳过"会使该文件 0 新增，故需 P5（只填空、不覆盖）让例句落到存量条目上。
- **三个口径澄清**：三段式 session 结构所有活动类型共用；连续天数按"到达结算页"计算；达今日目标可在组间过渡页提前结算。
- **接受"无独立学阶段"实现**（2026-10-05）：编码 agent 诚实说明——独立"学"阶段会使 `exposureCount` 1→2，与既有 `vertical-loop.test.ts` 断言冲突，在"不重写已有测试"约束下刻意不做。产品层面亦认可：热身与学阶段展示内容完全相同，重复只会拉长流程；热身即"学"，三态自评保留在 recall 作答链路。如未来需要完整学阶段，需同步更新该断言，另议。

**刻意不借的竞品机制**（2026-10-03 竞品调研结论，v0.3 不做）：
- 图词配对（7405 词配插图成本不现实）、社交/PK/互助批改（单人 dogfood 阶段不需要）、防断签/freeze 类机制（宪法禁止绑架式游戏化）。
