## 1. 背景与目标

v0.1 真实使用 1 天验证出关键 friction：**知识库完全依赖手动添加，效率极低**；而 Scheduler 的推荐、Learner Model 的学习全部依赖知识库——没有素材，V0 的验证闭环无法运转。

**目标**：
1. 让用户在一天内把知识库充实到"可验证推荐质量"的体量；
2. 知识库的所有操作可追溯；
3. 建立词库池 → 学习的流转机制，让导入的素材真正进入学习流；
4. 建立多目标体系，让 scheduler 的推荐有目标可依。

**非目标**：做成完整的内容平台。视频链接自动拉取、网页/PDF/播客 pipeline、多源持续同步仍在 V1。

## 2. 范围

### 做（In）
- **F1** 词库文件导入（CSV / JSON / TXT）：CET-4/6、雅思、词典
- **F2** 文本/字幕粘贴导入：LLM 提炼关键表达 → 人工确认 → 入库
- **F3** 知识库导出（JSON / CSV）
- **F4** 导入导出历史记录

- **F7** 目标体系：多目标主次、每日计划产品化、场景（树形）管理

### 不做（Out，留在 V1）
- 视频链接自动拉取（YouTube / Bilibili）
- 网页 / PDF / 播客导入 pipeline
- 多源持续同步、增量更新
- 系统从对话自动推断场景（v0.2 只做用户手动声明场景）

## 3. 功能需求

### F1 词库文件导入

- **支持格式**
  - CSV：列为 `word, phonetic, pos, definition, example`（phonetic/pos/example 可空）
  - JSON：对象数组，字段同上（格式见附录 A）
  - TXT：每行一个词（仅 content，无释义）
- **流程**：上传 → 解析预览（前 20 条 + 总数 + 预估去重数）→ 用户确认 → 执行 → 结果报告（新增 X / 重复跳过 Y / 失败 Z 及原因）
- **去重规则**：按 `(language, normalized_content)` 去重（大小写/首尾空格归一化）；库中已有的跳过并计数
- **幂等**：同一文件重复导入必须 0 新增。用文件 hash 识别（存于导入历史），二次导入直接返回"重复导入"结果，不写库
- **词库池隔离**（关键设计）：导入条目进入"词库池"（`status = new`），**不得**直接进入 SRS 到期队列。Scheduler 只调度 `learning`/`due` 状态条目
- **导入时绑定目标（可选）**：上传向导允许选择"这个词库服务于哪个目标"，写入词库级元数据，供 F6 相关性打分使用
- **大文件**：事务性批量写入；超过 1000 条显示进度；单次上限 20000 条，超限拒绝并提示分批
- **License 红线**：仓库**不得**提交版权不明的词库文件；提供手写 sample（`data/samples/sample-wordlist.csv`，十几条即可）供测试；文档注明推荐的开源词源（如 ECDICT）

### F2 文本/字幕粘贴导入

- **输入**：标题（可选）+ 文本（单次 ≤ 8000 字符，超长需分段提交）
- **LLM 提炼**（AI Level 2，高价值区）：输出**结构化 JSON**数组，每项 `{content, type, explanation_zh, example, source_span, scenario_hint?}`，其中 `type ∈ {word, phrase, pattern}`，`scenario_hint` 为可选的场景标签建议
- **人工确认**（强制）：提炼结果以列表呈现，可勾选/编辑/删除（含 scenario_hint 可改）；**只有用户点确认后才入库**，禁止 blind import；确认时可勾选"直接进入学习"
- **来源标注**：每条入库 `source = 文本标题 + source_span`，`ai_generated = true` 必须标识（宪法：AI 生成内容不得伪装成真实语料）
- **降级**（无 LLM Key 时）：文本仍可保存为 ContentSource，走现有手动添加流程；界面明确提示"提炼不可用"，不得报错、不得阻塞

### F3 知识库导出

- 范围：全部或按当前筛选条件；格式：JSON（全字段）/ CSV（`word, definition, example, status, mastery`）
- 走现有导出通道（如 `/api/export` 可复用则复用）；浏览器直接下载文件

### F4 导入导出历史记录

每条记录包含：`id`、`type`（import/export）、`method`（file-upload/paste/manual）、来源标识（文件名 / 词库名 / 文本标题）、文件 hash（导入）、格式、总数/新增/重复/失败数、`status`（成功/部分成功/失败）、错误明细、时间。

- 知识库页面新增"历史" Tab，按时间倒序展示

### F5 知识库操作日志

- 记录**所有**变更操作：手动增/改/删、导入、导出（导出只记元数据，不记内容）、加入学习/暂停回池、目标/场景变更
- 每条：时间、操作类型、对象（knowledgeItem id + content 摘要）、变更前后（关键字段 diff）、来源（manual/import）
- **与 LearningEvent 区分**：LearningEvent 记录学习行为（不可变事实，Learner Model 唯一来源）；操作日志记录数据管理行为。两表独立，互不干扰
- 日志不可删（"删除全部本地数据"除外）

### F6 词库池 → 学习流转

**问题**：导入的词默认进入"词库池"（`status = new`），必须有机制流转到"学习中"，否则是死数据。

**三条通道**：
1. **手动**：词库池浏览页，单个/批量"加入学习"（`new → learning`）
2. **自动**：scheduler 每日按目标相关性打分从池中捞取 ≤ 每日新词预算 个新词
3. **场景**：F2 确认时可勾选"直接进入学习"；场景激活时优先调度其关联表达

**流量阀：每日新词预算**
- 默认 10/天，用户可在设置调整（0–50）；设为 0 = 关闭自动引入，只走手动
- 按自然日重置；只计"新引入"，不计复习

**目标相关性打分**（确定性，权重集中配置，禁止散落）：
```
relevance = w1·词库绑定（该词库是否绑定到主目标）
          + w2·标签匹配（目标关键词 ∩ 词/词库标签）
          + w3·技能缺口（1 − 相关技能 mastery）
          + w4·词频归一化
          + w5·图谱关联（与近期已学条目的 related 关系）
```
- **Fallback 链**：无绑定/无标签时退化为词频 + 通用排序，**保证永远有输出**，不得出现"推荐为空"
- **可解释**：每条推荐的 reason 必须说出依据（如"来自你绑定的雅思词库"）；用户看不懂的"智能"等于没智能

**反向流转**：掌握（mastered）的词退出日常轮转；用户可随时"暂停"回池子（`learning → new`，保留历史证据不删除）

### F7 目标体系与场景

**三层（只有第一层由用户手动设定）**：

**1. 大目标（Goal）：可多个，必须分主次**
- `goals` 表新增 `priority`（primary/secondary）；同时只能有一个 primary
- 用户可在目标页切换主攻目标；切换后今日计划重新生成（至少下次打开时生效）
- 多目标不分主次会稀释推荐——这是本设计要解决的核心问题

**2. 每日计划（Daily Plan）：由 scheduler 生成，不由用户手设**
- 复用现有推荐 pipeline（**禁止重写 scheduler**）；UI 层包装为"今日计划"
- 呈现：预计总时长 + 任务列表 + **一键开始**
- 调整入口："换一批"（排除当前批次后重新调度，**不是随机**）、"今日休息"（今日不再推荐/打扰）
- 交互铁律：直接呈现，不让用户每天做配置；把负担还给用户的设计一律否决

**3. 场景（Scenario）：树形，大场景挂小场景**
```
大场景：下周去国外旅游（time_context: 下周 → 紧迫度高）
  ├── 小场景：饭店点餐
  ├── 小场景：酒店入住
  └── 小场景：问路打车
```
- 结构：`id, goal_id?`（可空，场景可独立于目标）、`parent_id?`（小场景挂大场景）、`name, type(big/small), time_context?, status(active/done)`
- **来源**：v0.2 只做用户手动声明（场景 CRUD + 绑定目标）；系统从对话推断场景并请用户确认 → V1（推断的场景绝不能偷偷生效）
- **使用**：场景激活时，scheduler 按"场景相关性 × 时间紧迫度"加权；小场景表达掌握度聚合 → 大场景准备度（如"旅游英语准备度 72%"）
- **生命周期**：`time_context` 过期后自动归档（active → done），停止加权

**关系链**：大目标 →（绑定词库/场景）→ scheduler 每日生成今日计划 → 学习 → 学习事件 → 大目标进度回流（目标页：词汇覆盖率、薄弱技能趋势）。

## 4. 数据模型（需求级，实现细节由编码 Agent 定）

- `KnowledgeItem`：复用 `status = new` 表达"词库池"（明确不进入 due 队列）；`source` 字段承载来源标识（含词库名/文本标题/场景）；新增 `ai_generated` 布尔标识。命名与风格遵循现有 `schema.ts`

- 新增表（建议名）：`import_export_history`、`knowledge_operation_log`，字段见 §3 F4/F5
- 幂等键：`import_export_history.file_hash`；去重依赖 `(language, normalized_content)` 唯一性保证（约束或等效逻辑）

- **首页**："今日计划"卡片（预计时长 + 任务列表 + 一键开始 + 换一批 + 今日休息），复用现有推荐 pipeline

- **设置页**：每日新词预算

## 6. 非功能需求

- 性能：1 万条导入 < 30 秒（本地）；万级词库池浏览不卡死；UI 全程有进度反馈
- 幂等：重复导入同一文件 0 新增（验收硬指标）
- 回归：现有 97 测试全过；新增单元/集成测试覆盖去重、幂等、池/学习隔离、相关性打分 fallback、日志完整性、无 Key 降级
- 宪法遵循：去重/解析/调度/打分走确定性规则（Level 0），LLM 仅用于 F2 提炼；提炼输出结构化、可降级、可标识
- 成本可观测：F2 每次提炼的 token 消耗记入现有遥测（telemetry 已有 token 计数，顺手接入），为后续成本分析留数据

## 7. 验收标准

1. 导入 4000 词 CSV：新增数正确（含去重），全部 `status = new`，SRS due 队列新增为 0
2. 同一文件导入两次：第二次新增 0，历史记录显示"重复导入"
3. 粘贴 2000 字英文演讲稿：提炼出 ≥ 10 条表达；用户取消勾选 2 条后确认导入，库中新增 8 条且 `source` / `ai_generated` 标注正确
4. 无 Key 环境：粘贴文本可保存为内容源，后续手动添加可用，无报错
5. 导出 JSON 后导入空库：条目一致（round-trip）
6. 手动删除 1 条、修改 1 条：操作日志中各有 1 条记录，含变更前后
7. 绑定雅思词库到"雅思 7 分"（主目标）后，次日计划中新词 ≥ 80% 来自该词库；reason 可解释
8. 每日新词预算设为 5：连续 3 天，每日新引入 ≤ 5；设为 0 则自动引入停止，手动加入仍可用
9. 激活"下周旅游"场景：计划中旅游场景表达占比显著高于未激活时；场景过期后自动归档，加权消失
10. 切换主攻目标：下次打开首页，今日计划内容随之变化
11. 无绑定/无标签的新目标：推荐不为空（fallback 生效），内容为词频排序的通用词
12. 存量升级：v0.1 唯一目标自动成为 primary；存量 knowledge 条目 `ai_generated` 默认为 false，功能无回归
13. `npm run verify` 全过

## 8. 里程碑（编码 Agent 可合并但不可跳过验证）

- **M1**：数据模型（history/log/scenarios 表、goals priority、budget 偏好）+ 去重/幂等逻辑 + 单元测试
- **M2**：F1 文件导入（含向导：上传/预览/确认/执行，含词库绑定目标）
- **M3**：F4 历史 + F5 操作日志（含 UI）
- **M4**：F2 文本导入（LLM 提炼 + 人工确认 + 无 Key 降级 + scenario_hint）
- **M5**：F3 导出 + 空库引导更新 + 数据迁移（§11）
- **M6**：目标体系（多目标主次 + 场景 CRUD/绑定/生命周期 + 目标页 UI）
- **M7**：每日计划产品化（首页今日计划卡片 + 换一批/今日休息）+ 词库流转（相关性打分 + 每日预算 + 词库池浏览）+ 全量验收（§7）

**交付顺序说明**：M1–M5 为第一个可交付切片（导入/导出/日志先行可用）；M6–M7 随后。不得为了"一次到位"把 7 个里程碑并成一个大提交。

## 11. 红线重申

- 不为导入引入云同步 / 多用户 / 登录
- LLM 输出必须结构化、可降级、可标识；提炼结果必须经用户确认才入库
- 不提交版权不明的词库到仓库
- 不提前实现 V1 能力（视频链接自动拉取、系统推断场景等）
- 不重写 scheduler 确定性核心；相关性打分是新增模块，不是替换
