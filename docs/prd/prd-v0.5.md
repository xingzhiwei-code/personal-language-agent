# PRD-v0.5：数据与画像层（全量词关系 + 搭配 + 起点自动校准）

> 版本：v0.5（已确认 2026-10-17）｜ 日期：2026-10-16
> 地位：V0 阶段内的第五次可交付迭代
> 目标读者：编码 Agent——读完直接开工，不需要再问"这个功能到底要怎么做"
> 前置阅读：`product/product-master-plan.md`（宪法与红线）、`docs/prd/prd-v0.4.md`（§3 G3 语义聚类 / §11 留 v0.5 项）、`docs/decisions/ADR-010.md`（§3 词关系方案 A / §5 诚实 scope）
> 背景输入：v0.4 交付后用户真实 dogfood 两天（2026-10-10~16）——"基本功能差不多了"；ADR-010 要求"v0.5 重新评估起点自动校准与搭配词典时，需先有 v0.4 的真实使用证据"，现已具备。

---

## 1. 背景与目标

v0.4 建好了架子（起点→阶段→语义聚类→路径），但架子是半空的：

1. **词关系数据只有约 140 词的精选子集**：v0.4 的"每日一主题、组内按关系排序"在小数据集上跑得起来，但稍偏离精选词就 fallback 回裸推荐——"主题成网"的体感断断续续。
2. **搭配（collocation）缺席**：v0.4 以"同话题共现"近似，但"学搭配"（如 make a decision / take responsibility）是词汇进阶的核心，近似值撑不起。
3. **起点是静态的**：v0.4 的起点来自摸底/自述，之后不再动。学了两周的人和第一天的人画像一样——画像不生长，推荐理由的"缺口"子句越往后越不准。

**目标**：把 v0.4 的架子填实——词关系数据全量可用、搭配上线、画像随学习数据持续生长。**本版零新交互**，全部是数据层与画像层的工作。

**非目标**：任何 UI 大改；主动推送/机器人教练；口语对话、发音评测（后续版本）。

**主题句**：v0.4 建架子，v0.5 填数据。

---

## 2. 范围

**W1 全量 WordNet**：词关系数据从精选子集扩展到全量（同义/反义/词族/话题全覆盖）；离线一次导入，运行时零新增 LLM 依赖（ADR-010 §3 延续）。
**W2 搭配（collocation）**：新增搭配关系类型；卡片展示搭配标签；组内排序纳入搭配。
**W3 起点自动校准**：画像随学习数据持续修正（v0.4 为静态起点）；校准走"建议 + 用户确认"模式，推断绝不偷偷生效（ADR-010 红线延续）。

---

## 3. 功能需求

### W1 全量 WordNet：从精选子集到全量

**数据策略**（yiyi 拍板，编码 Agent 直接执行，不二选一）：
- **以用户词库为锚点过滤**：只导入锚点词表内词的关系边。锚点词表 = 现有 `cet6-wordlist.csv` + `ielts-wordlist.csv`（goal workspace `files/` 下已有）+ 用户已学词。**不做全 WordNet 无过滤导入**（~15 万词形，绝大多数是用户十年内学不到的词，导入即浪费）。
- 关系类型沿用 v0.4 四种：`topic | synonym | antonym | word_family`；`source` 标记 `wordnet|topic_list` 不变。
- 预期量级：锚点词万级 → 关系边数万级（编码 Agent 导入后在 PR 中贴实际数字）。

**实现**：
- 复用 `scripts/import-word-relations.ts`，升级为支持全量模式（幂等、可重跑、可断点续跑；全量跑完前不删旧子集数据，跑完做一致性校验后切换）。
- `word_relations` 表结构不动（`wordLemma` 索引已有）；若查询性能下降，加复合索引而非改结构。
- **License spike**（约半天，M1 开工前）：确认 WordNet 数据的 license 允许本项目使用方式（WordNet 3.1 为 Princeton 许可，需保留版权声明；若用 npm `wordnet` 包，检查其 bundle 的数据版本与 license 文件），结论写进 PR 描述。License 有问题 → 停下报 yiyi，不得静默换数据源。

**Scheduler 行为变化**：
- 主题聚类 fallback 触发率应显著下降（编码 Agent 在 PR 中贴 fallback 率前后对比：用 v0.4 子集跑 7 天 vs 全量跑 7 天的主题词命中率）。
- 组内排序、卡片关系标签逻辑不变（v0.4 §3 G3），只是数据变多了。

### W2 搭配（collocation）

**数据源 spike**（约半天，M2 开工前，先于实现）：
- 验证公开搭配词典/搭配数据的可得性与 license（候选：公开搭配词表、基于语料统计的搭配抽取；编码 Agent 定并在 PR 贴来源链接）。
- **任一不可得 → 降级**：搭配不上线，继续用"同话题共现"近似 + 诚实标注（v0.4 现状），**不得阻塞 W1/W3**。降级决定由编码 Agent 在 spike 结论中明确写出，不需要再问。

**实现**（spike 通过后）：
- `relationType` 新增 `collocation`（`word_relations` 表加值，不加表；`ai_generated=false`，来源标注）。
- 锚点策略同 W1：只收锚点词的搭配。
- 卡片展示：搭配标签（如"🔗 搭配：make a decision"），只读曝光，不计分（沿用 v0.4 关系标签口径）。
- 组内排序：核心词 → 搭配 → 同义/反义/词族 → 同话题（搭配优先于同义反义，因为搭配更直接服务于"会用"）。

### W3 起点自动校准：画像随学习数据生长

**现状**：v0.4 起点 = 摸底/自述/手动覆盖，静态；UI 诚实标注"静态起点"。

**目标**：每积累 N 个学习日（默认 14，集中配置）的有效学习数据后，系统重新估算起点段位；估算变化 ≥0.5 band 时，向用户发出一次**校准建议**（非强制、不弹窗打扰，放在目标页/首页轻提示）。

**规则**（确定性，阈值集中配置）：
- 估算输入：近 N 个学习日的 mastery 分布、复习正确率、小测成绩（现有数据，不新增采集）。
- 估算输出：`{ scale, value, confidence, evidence: ['auto_calibration'], basedOn: '近14天学习数据' }`，写入 `placements` 新 type=`auto_calibration`（与 test/self_report/override 并列，历史可追溯）。
- **用户确认模式**：建议文案如"根据你近 14 天的学习数据，你的水平可能在 5.0 左右（之前是 4.5），要更新吗？"→ 用户点"更新"/"保持不变"/"去重测"。**不点 = 不生效**（沿用 ADR-010"推断绝不能偷偷生效"红线；v0.4 否掉的"系统从对话推断水平并偷偷调阶段"同样适用于此）。
- 幅度保护：单次校准变化不超过 1.0 band（防抖动）；confidence 随证据量提升（low→medium→high），UI 诚实展示。
- 手动覆盖永远优先：用户点过"手动调整"后，自动校准暂停，直到用户重新开启（目标页开关）。

**UI**：目标页起点卡片增加"自适应起点 · 开/关" + 校准历史（只读时间线）；首页不新增常驻元素（校准建议走轻提示，宪法#10 不打扰）。

## 4. 数据模型（需求级，实现细节由编码 Agent 定）

- `word_relations`：`relationType` 新增 `collocation` 枚举值；其余不动。导入脚本支持"锚点过滤 + 幂等重跑 + 断点续跑"。
- `placements`：`type` 新增 `auto_calibration`；payload 含 `basedOn`（数据窗口说明）。
- 新增配置项（集中配置，不散落代码）：锚点词表清单、校准周期 N（默认 14 学习日）、校准触发阈值（≥0.5 band）、单次最大变化（1.0 band）。
- 其余复用现有 schema；命名与风格遵循现有 `schema.ts`。

---

## 5. UI/UX

- **无新增页面**。W1/W2 对用户无感（推荐变准、fallback 标注变少）；W3 只在目标页起点卡片加"自适应起点"开关 + 校准历史时间线 + 一次轻提示。
- **气质红线**（延续）：校准建议文案禁止焦虑（"再不更新就测不准了"类禁止）；假设透明化（confidence/evidence 可见）；校准历史时间线只读展示，不可删改。
---

## 6. 非功能需求

- **运行时零新增 LLM 依赖**：词关系/搭配离线一次生成；校准为确定性计算。宪法#4（AI Economy）遵循。
- 回归：现有全部测试全过；新增单元/集成测试覆盖：导入脚本幂等性、锚点过滤正确性、搭配排序位置、校准阈值边界、"不点不生效"、手动覆盖后暂停、降级路径。
- 性能：`word_relations` 数万级查询不卡；scheduler 每日生成耗时不得显著增加（基线由编码 Agent 实测记录）；全量导入脚本单次运行时间编码 Agent 记录，超过 2 小时需上报。
- 数据诚实：license 无结论不得入库；搭配降级时必须在日志/PR 中明确标注。
- Node 约束沿用 v0.3（P3）：Node 20。

## 7. 验收标准

**W1 全量 WordNet**
1. 导入脚本幂等：连续跑两遍，`word_relations` 行数不变（不翻倍）。
2. 锚点过滤：抽查 20 个非锚点词（如生僻词），无关系边；抽查 20 个锚点词（CET6/IELTS 词表内），关系边完整（同义/反义/词族至少一种）。
3. 主题词命中率：全量导入后，主题 fallback 触发率显著低于 v0.4 子集时期（编码 Agent 贴 7 天对比数字，目标下降 ≥50%）。
4. PR 贴出：锚点词数、关系边总数、WordNet license 结论。

**W2 搭配**
5. （spike 通过）抽查 20 个锚点词，搭配边存在且来源标注正确；卡片可见搭配标签；组内排序中搭配排在同义/反义之前。
6. （spike 不通过）M2 跳过，代码无搭配逻辑残留；降级有明确标注（日志/PR 注明"搭配数据源不可得，沿用话题近似"）。

**W3 起点自动校准**
7. 构造 14 个学习日数据使估算变化 ≥0.5 band → 目标页出现轻提示（非弹窗）；点"更新"后 `placements` 新增 `auto_calibration` 记录且起点更新；点"保持不变"后无记录、无变化。
8. 构造估算变化 2.0 band 的数据 → 单次校准变化 ≤1.0 band。
9. 用户手动覆盖起点后，自动校准暂停（不再发提示），直到重新开启开关。
10. 校准历史时间线只读展示，含 `basedOn` 数据窗口说明；无时间承诺文案、无焦虑文案。

**回归**
11. `npm run verify` 全过；Playwright 走查（v0.3/v0.4 同款旅程）回归通过，无体验倒退。

- 无破坏性变更；`word_relations` 在旧子集上增量导入（先不删旧数据，一致性校验后切换）；`placements` 只增新 type 记录。

## 11. 决策记录

**三个拍板决策**（2026-10-16/17，用户）：
1. **v0.5 范围三项**：W1 全量 WordNet、W2 搭配、W3 起点自动校准；一次只做一个迭代；v0.6+ 暂不规划、不出现在文档中。
2. **W1 锚点词表过滤**：只导入锚点词的关系边，不无脑全导；license spike 先行，有问题停下报。
3. **W2 先 spike 后降级 + W3 确认模式**：搭配数据源不可得则降级（同话题共现近似 + 诚实标注），不阻塞；起点自动校准走"建议 + 用户确认"，推断绝不偷偷生效。

**诚实 scope**（yiyi 建议）：
- license 无结论的数据不得入库。
- 搭配降级必须在日志/PR 中明确标注，不得静默。
- 画像是"假设"不是"事实"：校准变化必须让用户知道（轻提示 + 历史时间线），confidence/evidence 可见。
