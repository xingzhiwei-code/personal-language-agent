# ADR-005：AI 经济性——Level 0–3 分级；省 token 绝不牺牲 UX

- 日期：2026-09（产品定义讨论第 8 轮；由用户主动提出并坚持）
- 状态：已采纳（产品宪法第 04、05 条）

## 背景

用户提出："Agent 必须要尽可能少消耗用户的 token，能复用开源就尽量不用大模型；但决不可因为替用户省 token 而降低用户体验。"

## 决定

两条宪法**必须同时存在、相互制衡**：

- **04 AI Economy**：能不用大模型就不用；能用规则就不用模型；能用开源/小模型就不用大模型。
- **05 Never Sacrifice UX for Cost**：如果省 token 会让用户多等、多点、体验变差，那就用大模型——省钱不能让用户感知到。

落地为 **AI 调用四级框架**，每个 AI 调用在代码注释中标注 Level，Code Review 时检查"这个功能真的需要这个 Level 吗"：

| Level | 成本 | 适用 |
|-------|------|------|
| 0 纯规则 | 0 token | SRS 调度、复习提醒、查词典、本地匹配 |
| 1 小模型/开源 | 便宜 | 简单分类、意图识别、拼写检查（未来可本地跑） |
| 2 大模型 | 贵但值 | 自由对话、复杂纠错、个性化解释——"高价值区" |
| 3 多模型协作 | 最贵，慎用 | 仅高价值场景，如深度写作批改 |

## 被否掉的选项

- **只写"省 token"不写制衡**：单条"省 token"宪法会被执行成抠门实现（多等 3 秒、多点 2 次），损害最高宪法（UX First）。
- **"大模型随便用，以后再优化"**：成本归属（以后给别人用谁买单）、延迟（3 分钟场景等 30 秒直接崩）、可替换性（深度绑定后想换模型/离线全得重写）三个问题决定了必须一开始就分级。

## 后果

- v0.1 落地：`tests/architecture/boundaries.test.ts` 用静态检查禁止 `learner/scheduler/assessment/nlu` 目录调用 LLM（Level 0 硬约束）。
- 优化目标定义为 `Learning Value / Compute Cost`，成本内部可观测（Daily/Session/Task），永远不对用户哭穷（"你的 token 不够了"永不出现）。
