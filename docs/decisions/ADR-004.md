# ADR-004：存储——V0 全本地；ObjectStorage 接口预留，不上 COS

- 日期：2026-09（产品定义讨论第 6 轮；用户主动询问腾讯云 COS）
- 状态：已采纳

## 背景

用户有腾讯云 COS 的团队使用经验，询问是否要用。需要明确 V0 的存储策略。

## 决定

**V0 全部本地**：

- SQLite 存结构化数据（Learner Model、Memory、学习事件、SRS 状态）；
- 本地文件系统存非结构化数据（录音、文章、生成的练习）；
- 不上 COS，不上任何云，不做云同步。

同时**必须预留 `ObjectStorage` 抽象接口**（`put/get/delete`），V0 用 `LocalObjectStorage` 实现；Domain 层禁止出现任何云 SDK 的 import（如 `tencentcloud-sdk`、`cos-nodejs-sdk`），配置文件不硬编码 bucket/region。

## 被否掉的选项

- **V0 直接上 COS**：V0 的目标是验证"大脑"好不好用，不是验证云架构；上云意味着配密钥、调权限、看文档、可能扣费，只会拖慢验证。用户之前团队的 COS 经验"暂时用不上，但以后会很有用"。
- **不预留接口、以后再说**：`learning_events` 是 append-only（带幂等键，天然适合增量同步），现在抽象好接口，V1 要做多设备同步时换实现即可，Domain 零修改。

## 后果

- 数据隐私成为架构特性：学习数据默认不出设备（见宪法；设置页提供一键导出/删除）。
- V1 评估多设备同步时再选 COS/S3/R2；且必须先解决"多设备并发写 SQLite"的语义问题（见方向决策文档）。
