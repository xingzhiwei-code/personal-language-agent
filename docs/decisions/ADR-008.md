# ADR-008：F1–F7 从 V1 提前到 V0.2——先让验证闭环转起来

- 日期：2026-10-02（v0.2 PRD 定稿）
- 状态：已采纳
- 对应 PRD：`docs/prd/prd-v0.2.md`（F1–F7：知识库导入/导出、操作日志、词库流转、目标体系）

## 背景

Master Plan 第 167 条规定："当前只实施当前版本（如 V0.1），不得提前实现 V1/V2 能力。"F1–F7 原属 V1 范围。v0.1 真实使用 1 天后验证出关键 friction，迫使我们显式推翻这条约束——故立此 ADR。

v0.1 的 friction（PRD-v0.2 §1 原文）："**知识库完全依赖手动添加，效率极低**；而 Scheduler 的推荐、Learner Model 的学习全部依赖知识库——没有素材，V0 的验证闭环无法运转。"

## 决定

把 F1–F7（词库文件导入、文本/字幕粘贴导入、知识库导出、导入导出历史、操作日志、词库池→学习流转、多目标体系）从 V1 **提前**到 V0.2，目标只有四个（PRD-v0.2 §1）：

1. 让用户在一天内把知识库充实到"可验证推荐质量"的体量；
2. 知识库的所有操作可追溯；
3. 建立词库池 → 学习的流转机制，让导入的素材真正进入学习流；
4. 建立多目标体系，让 scheduler 的推荐有目标可依。

**提前有边界**：只提前"让验证闭环转起来"所必需的最小集合。以下仍在 V1，不提前（PRD-v0.2 §1 非目标 + §11 红线）：视频链接自动拉取、网页/PDF/播客导入 pipeline、多源持续同步、系统从对话推断场景。

## 被否掉的选项

- "按原计划等 V1 再做导入"——那 V0 的 scheduler 推荐质量永远验证不了；验证前置依赖缺失，不是"可以等等"的事。
- "干脆把完整内容平台一起提前"——那是真膨胀；导入是" validated learning 的前置条件"，内容平台是"规模化的舒适区"，两者性质不同。

## 后果

- "提前实现高版本能力"此后必须立 ADR：写明提前的是什么、为什么等不及、不提前的边界是什么，不得静默提前。
- V1 能力清单不变；任何 PR 以"ADR-008"为由夹带 V1 能力（如视频 pipeline），必须重新决策。
