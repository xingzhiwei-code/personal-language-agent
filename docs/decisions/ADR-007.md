# ADR-007：V0 不做清单——游戏化、社交、黑盒发音打分

- 日期：2026-09（产品定义讨论第 1、3、9 轮）
- 状态：已采纳

## 背景

"不做什么"与"做什么"同等重要。以下三项在讨论中被明确排除出 V0（乃至更久）。

## 决定

### 1. 不做游戏化（streak / coins / leaderboard / lives / 惩罚）

- **理由**：游戏化优化的是打开率（App Engagement），不是能力（Real-world Capability）；"连续打卡断了就清零"是惩罚机制，与"遗忘是正常的，不羞辱用户"的产品哲学冲突。
- **区分**：不要"游戏化绑架"，但要"成就感"——"你这个月掌握了 50 个新表达，其中 10 个已在真实对话里用过"（用户成长）vs "你已连续打卡 30 天！"（App KPI）。
- 状态：**有意为之**的产品选择，写入 README 已知限制。

### 2. 不做社交（V0 完全不做）

- **理由**：社交是双刃剑——好社区激励，坏社区制造焦虑（"别人都学得比我快"）；核心用户是自己，先把"私教"做好；社交是锦上添花，不是雪中送炭。
- **远期**：如果做，只做"学习搭子"（两人互相监督），不做排行榜。

### 3. 不用 AI 黑盒做发音打分（V0）

- **理由**：承认"开源发音评测不如商业的准"；用不准的黑盒打分会给出错误反馈，不如不用。
- **替代**：V0 用文字层面纠错（转录文本走确定性判分）；发音打分延后到 V1，届时再评估商业 API。

## 被否掉的选项

- "别人都有打卡，我们也加一个"——以差异化为由拒绝：local-first + 确定性 + 反游戏化本身就是卖点。
- "先接一个免费发音 API 占位"——不准的反馈比没反馈更有害（宪法 03 Learning Effectiveness）。

## 后果

- 任何 PR 引入 streak/排行榜/社交 feed，必须引用本 ADR 重新决策，不得静默加入。
- V1 重新评估社交与发音评测时，需先有 V0 的真实使用证据。
