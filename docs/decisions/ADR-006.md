# ADR-006：多语言——LanguagePack 架构；English First

- 日期：2026-09（产品定义讨论第 8 轮；由用户主动提出）
- 状态：已采纳（产品宪法第 06 条）

## 背景

用户要求：Agent 不要局限于英语，要能学所有语言；但如果复杂度指数提升，则英语最重要、日语韩语次之。

## 决定

关键洞察：**语言学习的能力是相通的，语言本身只是"数据"**。因此复杂度是线性而非指数的：

```
LearningCore（语言无关：LearnerModel / Scheduler / SRS / Memory）
    ↓
LanguagePack（语言相关）
    ├── EnglishPack   ← V0 实现
    ├── JapanesePack  ← V1
    └── KoreanPack    ← V1
```

```typescript
interface LanguagePack {
  language: string;              // 'en' | 'ja' | 'ko'
  phonetics: PhoneticsModule;    // 发音
  grammarChecker: GrammarChecker;// 语法纠错
  dictionary: DictionaryModule;  // 分词 / 词典
  speech: SpeechConfig;          // STT/TTS 配置
}
```

约束：核心 Domain **禁止出现具体语言硬编码**；V0 只实现 EnglishPack，但必须写一个"FakeLanguagePack 能否跑通"的测试来验证解耦。

## 被否掉的选项

- **只做英语、以后再说**：现在不隔离，以后每加一种语言都是指数级重构；接口预留成本很低。
- **V0 就做英/日/韩三语**：违背 English First；日语韩语完整实现是 V1 的事，V0 先把英语做深（通用回退可存可复习，但不假装有语言特有分析）。
- **为未来语言做大平台工程**：接口隔离 ≠ 过度工程；v0.1 禁止为"未来 N 种语言"提前做大平台（见执行宪法反模式）。

## 后果

- v0.1 落地：`src/language/registry.ts` 预留多语言注册表；除 English 外走通用回退，README 诚实声明。
- 长期：每加一种语言 = 加一个 LanguagePack，贡献者入口清晰（"如何加一门语言"是天然的开源 contributor 漏斗）。
