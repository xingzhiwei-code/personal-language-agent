# ADR-011：v0.5 数据与画像层——全量词关系、搭配与起点自动校准

- 日期：2026-10-17（用户确认开工）
- 状态：已采纳
- 对应 PRD：`docs/prd/prd-v0.5.md`

## 背景

v0.4（目标驱动学习路径）收版后，用户真实 dogfood 两天，反馈"基本功能差不多了"。ADR-010 要求"v0.5 重新评估起点自动校准与搭配词典时，需先有 v0.4 的真实使用证据"——现已具备。

v0.4 建好了架子（起点→阶段→语义聚类→路径），但三处是半空的：词关系数据只有约 140 词的精选子集（稍偏离就 fallback 回裸推荐）、搭配缺席（v0.4 以"同话题共现"近似）、起点静态（学两周的人和第一天画像一样）。

## 决定

### 1. v0.5 范围三项，一次只做一个迭代（用户拍板）

W1 全量 WordNet、W2 搭配（collocation）、W3 起点自动校准。v0.6+ 暂不规划、不出现在文档中（用户要求，2026-10-16；后续可能变动或先做其他）。

### 2. W1 数据策略：锚点词表过滤（yiyi 拍板）

只导入锚点词的关系边——锚点 = CET6/IELTS 词表 + 用户已学词。**不做全 WordNet 无过滤导入**（十几万词形，绝大多数是用户十年内学不到的词）。License spike 先行：结论写进 PR；license 有问题停下报 yiyi，**不得静默换数据源**。

### 3. W2 降级策略：先 spike，不可得则降级，不阻塞（yiyi 拍板）

先验证搭配数据源可得性与 license；不可得 → 降级为"同话题共现近似 + 诚实标注"（即 v0.4 现状），**不得阻塞 W1/W3**。降级不丢人，阻塞丢时间。

### 4. W3 确认模式：建议 + 用户确认，推断绝不偷偷生效（用户拍板方向，yiyi 落条款）

起点自动校准走"建议 + 用户确认"：估算变化 ≥0.5 band 时发一次轻提示（非弹窗），用户点"更新"才生效，**不点不生效**（ADR-010 推断红线延续；画像是"假设"不是"事实"，变了必须让用户知道）。单次变化 ≤1.0 band 防抖动；用户手动覆盖后自动校准暂停，直到重新开启。

### 5. 文档偏好（用户亲口，2026-10-16）

PRD 不再设"不做/Out"节；约束性"别碰"只写进给编码 agent 的任务书——那才是真正管住 agent 的地方。

## 被否掉的选项

- "全量无过滤导入 WordNet"——导入即浪费，且查询性能风险。
- "搭配数据源不可得时阻塞等待"——v0.4 已验证"话题近似"可用。
- "静默自动校准"——违反宪法#2（用户最终决定权）与 ADR-010 推断红线。
- "v0.5 顺手做 UI/发音/主动"——一次一个迭代，用户明确叫停。

## 后果

- 任何 PR 引入静默画像变更、无 license 结论的数据源、或阻塞式等待搭配数据，必须引用本 ADR 重新决策，不得静默加入。
- W1 交付的 fallback 率前后对比数据，作为后续版本规划的输入证据之一。
- `docs/decisions/README.md` 索引已同步。
