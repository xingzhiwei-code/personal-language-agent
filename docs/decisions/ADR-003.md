# ADR-003：交互形态——大脑/皮肤分离；V0 只做网页版

- 日期：2026-09（产品定义讨论第 4 轮）
- 状态：已采纳

## 背景

"最终是个什么形式"决定技术选型：桌面端、手机 App、Siri 式语音助手、浏览器插件，各有利弊，选错重写成本高。

## 决定

不把 Agent 想成一个 App，而想成**三层**：

1. **大脑（Brain）**：Learner Model + Scheduler + Agent 编排——核心，与形式无关；
2. **嘴巴和耳朵（Interface）**：STT / TTS / 文字——负责交互；
3. **皮肤（Skin）**：App / 插件 / 网页 / 语音——用户看到的样子，可多个，共用大脑。

**V0 只做网页皮肤**：开发最快，手机电脑都能用，不用上架；浏览器自带麦克风，语音能力可跑。先验证"大脑"，不在"皮肤"上浪费时间。

## 被否掉的选项

- **V0 直接做手机 App**：投入大，且过早绑定形式；应在网页版验证通过、"觉得有个 App 更方便"时再做。
- **桌面端独立应用**：投入大，覆盖场景与网页版重叠。
- **Siri 式随时唤醒**：技术复杂（常驻后台、语音唤醒），且 iOS/Android 不向第三方开放真正的系统级唤醒。
- **先选形式再定体验**：形式为体验服务；"每天早上 5 分钟口语"适合 App，"读文档时查"适合插件——应先定 V0 验证哪个场景。

## 后果

- 大脑代码与 UI 无关；加新皮肤时大脑零修改（架构约束）。
- 长期畅想"随身英语私教"（推送 + 通勤听力 + 插件划词 + 晚间对话 + 睡前报告），但那是 V1/V2 的事，V0 不许提前投入。
