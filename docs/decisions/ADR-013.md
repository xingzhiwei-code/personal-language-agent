# ADR-013：v0.5 验收——带诚实缺口收版；验收 #3 指标订正

- 日期：2026-10-17（yiyi 验收走查）
- 状态：已采纳
- 对应：`docs/prd/prd-v0.5.md` §7、`docs/acceptance-v05.md`

## 背景

编码 agent 交付 v0.5（M1/M3/M4），自测 221 tests + 13 e2e 全过（Node 20），并诚实报告一处缺口：验收 #3「主题词命中率：全量后 fallback 显著下降（目标 ≥50%）」未达成——实测前后均为 ~16%。

yiyi 走查确认：W1/W2/W3 均按 PRD §3 交付；typecheck/lint 通过；新增单元测试在 yiyi 环境通过；集成测试在 yiyi 环境因 Node 24 与 better-sqlite3（按 Node 20 编译）不兼容无法运行——属环境问题，非代码缺陷。

## 决定

**收版**，缺口不阻塞，原因：

1. **验收 #3 的指标是 PRD 写错了（yiyi 的问题，不是 agent 的）**。W1 的范围是 synonym/antonym/word_family 关系边（卡片标签 + 组内排序），从未包含 topic 标签；scheduler 的话题归属只读 `relationType='topic'`，W1 结构上就不可能改变它。正确的 W1 价值指标是**关系边覆盖率**（有关系边的词：~140 → 7405），这正是 dogfood 痛点「词孤立」的解法。
2. 话题标签覆盖需要更大的话题词表，无 license 清晰的公开数据源（与 W2 搭配同类情况），不可强求。
3. agent 如实报告未达标而非粉饰指标——按诚实原则应予接受，不应惩罚诚实。

## 被否掉的选项

- 「打回重做话题扩展」——无可用数据源，打回等于无限期阻塞。
- 「让 agent 用 WordNet 关系启发式推导话题标签」——属编造数据（话题归属是人工判断，不是词典事实），违反红线「缺数据不编造」。

## 后果

- 后续版本若重提「话题覆盖率」，必须先有话题词表的数据源 spike（license 先行），不得直接立项。
- PRD 验收指标必须与该版本的数据范围一致：数据只加了 X 关系，就只验收 X 关系的覆盖率，不验收 Y。
